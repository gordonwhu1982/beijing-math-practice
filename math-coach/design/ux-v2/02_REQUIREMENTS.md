# 02 需求基线（沿用 + 本轮补充）

来源：`../ux-redesign/01_REQUIREMENT_BASELINE.md`（已过 M1 门禁）+ 用户 2026-11-12 的新指令。本文件只做继承与收敛，不新造需求。

## 1. 用户与场景

- 主用户：初二学生，北京版数学八年级上册，正在学第 12 章三角形；也练第 11 章（二次根式/立方根）。
- 使用场景：家里平板横屏，一个人用，家长偶尔看进度。
- 不做：多用户、账号体系、教师端、手机小屏优化、离线安装包。

## 2. 五件事必须成立

| 编号 | 需求 | 现在的状态 |
|---|---|---|
| REQ-1 | 知道今天练什么（一组 6 题左右，含难度分层） | 原型有；数据用的是示意题 |
| REQ-2 | 做题时能求助但不白给（五级提示，看完整解析要记账） | 原型有；提示内容写死成三角形 |
| REQ-3 | 做完知道结果、错在哪、能回去看那个知识点再练 | 原型有；标题/主按钮写死 |
| REQ-4 | 能在知识图谱里按章—节—知识点走，也能从图谱直接做题 | 原型有（课本/图谱/分层三档）；图谱是列表+卡片，非力导向 |
| REQ-5 | 回顾：哪不稳、再测一次、记录变化 | 原型有；回顾只认示意题，题库作答进不来 |

## 3. 质量要求（用户反复强调的三条）

1. **不说假话**：界面上的数字、状态、文案必须与数据一致；截断、省略号、「还有 n 个」都要有据。
2. **不给死胡同**：每一屏都要有下一步；出错态（题没入库、知识点没找到、图没加载）也要给出口。
3. **验证要硬**：判据要能机器跑，覆盖多视口、多数据状态（空/有记录/有错题/有跳过），不能只在一个尺寸上点几下。

## 4. 本轮追加（2026-11-12）

- 基准不许改：以 v215/css181 为对照，任何改动要在 `app/` 里做，且能 diff 回基准。
- 工程化：原型是 7491 行单文件，本轮至少要让它**可分段维护**（数据层 / 视图 / 判分 / 样式分离），但不引入构建步骤（仍是 `<script>` 直挂）。
- 多角色：规划、设计、实现、验收分开，开发自测≠验收。
- 上游资产：`https://gordonwhu1982.github.io/beijing-math-practice/`（远端 Pages，含 `#old` 旧开源版）只作界面参考，不作为实现依赖。
