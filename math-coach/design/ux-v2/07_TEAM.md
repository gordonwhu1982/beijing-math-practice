# 07 团队与边界

## 角色

| 角色 | 干什么 | 写入范围 | 是否真实子 Agent |
|---|---|---|---|
| 项目经理（主会话） | 拆任务、合并、跑判据、提交、汇报 | 全仓（受各任务边界约束） | — |
| 产品 | 需求收敛、范围与优先级、旅程缺口 | 只写 `reviews/product.md` | 见下 |
| UX 研究/设计 | 交互与版面走查、可执行改法 | 只写 `reviews/ux.md` | 见下 |
| 前端架构 | 拆分方案、数据/记录契约、技术风险 | 只写 `reviews/arch.md` | 见下 |
| QA | 判据设计、负面验证、数据状态矩阵 | 只写 `reviews/qa.md` | 见下 |
| 开发 | 按任务改 `app/` | 任务卡指定路径 | 由主会话或成员执行 |

## 纪律（写给每个角色）

1. 只读代码与文档，**不改** `app/`、`tools/`、`../ux-redesign/`、`../../runtime/`、`../../content/`。
2. 每条结论必须带 `文件:行号` 或度量数字或截图路径；没有出处的判断标「推测」。
3. 先分清「界面缺陷」与「判据缺陷」——判据写错导致的假红会掩盖真问题。
4. 不重复 `03_FINDINGS.md` 已有的条目；有新证据就补证据，或提出新条目。
5. 报告用中文，标题按 `## P0 / ## P1 / ## P2 / ## 通过项 / ## 判据坑` 五段组织。

## 声明

本轮至少要有两条**独立于开发**的评审（产品/UX/QA 任意两条），否则不写「已验收」，只写「主会话自测」。
