# 第一阶段专项重构任务书

- 负责人：仓库主人提出，项目经理执行
- 版本：1
- 更新时间：2026-11-04
- 关联：ADR-010
- 状态：生效。执行状态以 `00_DESIGN_OVERVIEW.md` 为准

来源是仓库主人 2026-11-04 交给项目经理的任务书。这里保留约束和门禁，不改写范围。

## 目标

在理解现有产品、历史需求、实际工程、竞品和参考视频之后，重新设计信息架构、体验、视觉和交互，形成后续开发能直接使用的设计交付包。

当前阶段不改产品代码，不做架构重构，不启动开发。

## 角色

项目经理管范围和门禁。产品分析师管需求和现有功能。UX 管整体体验和信息架构。交互管操作和状态。UI 管视觉，且排在信息架构之后。竞品研究提供外部依据。独立评审员不负责自己评审过的那一版设计。

不能用一个会话模拟全部专业意见后宣布通过。已安装的角色配置不重建。

## 模型

核心岗位优先 `claude-opus-5-5`。2026-11-05 仓库主人明确：这个账号不能用该模型，其余工作用当前会话的默认模型做完，不因此整包停住。调用记录见 `docs/delivery/agent-validation/MODEL-OPUS-2026-11-04.md`。已安装角色仍是 `model: inherit`，不重建。

## 允许和禁止

允许读代码、启动现有工程、操作页面、准备测试数据、截图、在 `design/ux-redesign/` 里写设计稿和独立原型。

禁止修改业务源代码、组件实现、现有页面、数据结构和接口，禁止把原型接进当前产品，禁止为了展示新设计覆盖旧工程。

可以重做页面组织、导航、入口和交互。不得未经评审删掉已经确认的业务能力。要废弃或合并功能时，先记需求变化和理由。

## 门禁

上一阶段评审通过才进入下一阶段。

| 里程碑 | 通过时要能回答的事 |
|---|---|
| M1 | 产品是什么、用户是谁、有哪些功能、主要任务是什么、哪些已实现、哪些只是历史规划。缺口写明，不补成事实 |
| M2 | 主要页面有真实运行截图。没有现状基线，不做大规模新设计 |
| M3 | 竞品研究能指到具体页面、操作和来源。推断不能写成竞品已有能力 |
| M4 | 信息架构、页面结构和核心旅程已定，无明显功能遗漏和流程冲突。此门通过前，UI 不做全量页面 |
| M5 | 核心任务有进入、操作、反馈、取消和结束。主要页面状态有规格。一张静态图不算交互完成 |
| M6 | 设计系统和主要页面的视觉规格已定 |
| M7 | 原型能打开，核心路径能点。原型在 `design/ux-redesign/prototype/`，不替换现有页面 |
| M8 | 至少两轮交叉评审，其中一轮由没画这些页面的角色做。没有真实用户就不得写成真实用户测试。严重问题未处理不得宣布通过 |

## 交付目录

正式稿放在 `design/ux-redesign/`。截图分 `screenshots/current/`、`screenshots/references/`、`screenshots/proposed/`。真实运行截图和后来生成的效果图分开。

追踪关系：需求 → 功能 → 页面 → 用户任务 → 交互 → 界面 → 验收。

## 完成标准

后续架构和开发拿到交付包后，能知道产品应变成什么样、每页如何展示、用户如何操作、怎样判断实现符合设计。只有文档和文字建议不算完成。
