# M6 视觉复评

- 负责人：独立视觉评审员（只复评上一轮 M6 的两条严重项）
- 版本：0.1
- 更新时间：2026-11-05 +08:00
- 关联：`08_DESIGN_SYSTEM.md` 的 §0、§2.2、§3.1、§4.8、§5 开头、§5.7；`prototype/app.css` 的 `:root`。原型是 `prototype/index.html` 第 7 行的 `app.css?v=39`
- 状态：不通过。只复评这两条，不表示第一阶段通过

## 0. 审什么

上一轮 `18_REVIEW_M6.md` 有两条严重项：主要页面没有 2360×1640 的版面；字号不是一套，原型 13px 在 264 ppi 上约 3.5pt。

本轮只核这三件事：

1. 孩子能看到的最小字是不是 44px（264 ppi 上的 12pt）。
2. §2.2、§4.8 和 `app.css` 的 `:root` 是不是同一套字号。
3. 课本、章、知识点、测试、我的记录有没有 2360 画布上的区域尺寸。

有一条仍对不上，M6 就不通过。没有改代码，没有改设计稿，没有用浏览器点原型。

## 1. 结论

**不通过。**

字号令牌在 §2.2、§4.8 和 `:root` 已经是同一套，最小档是 44px。页面和组件里仍写着更小的字，原型还有一处写死的 28px，所以最小字不是 44px。课本、章、知识点、测试、我的记录仍没有落在 2360×1640 上的区域尺寸；六页表格里的宽和高也还是旧画布的数。

## 2. 严重 1：主要页面仍没有 2360×1640 的版面

画布声明已经对齐。`08_DESIGN_SYSTEM.md` §0 第 15–16 行、§3.1 第 125–135 行写的是 2360×1640、导航 320 / 160、内容区 2040 / 2200、可用宽 1944 / 2104、可视高度 1640。`prototype/app.css` 第 42–43 行是 `--nav-w: 320px`、`--nav-w-rail: 160px`，第 58–60 行的 `.stage` 是 `width: 2360px; height: 1640px`。这几处声明一致，不能代替下面仍对不上的区域尺寸。

### 2.1 六页表格仍是旧画布的数

§5 第 254 行把基准改成了「2360×1640 物理像素」，并写「下面表格里的宽如果和本节开头不一致，以本节开头的 1944 / 2104 为准」。这句只处理宽。表格里的高、y 和导航宽没有跟着改，同一节里仍有两套数。

| 位置 | 写的是什么 | 和 2360×1640 对不上的地方 |
|---|---|---|
| §3.2 第 143–148 行 | 标准导航 200 宽，窄栏 96 宽；产品名 20px，导航文字 18px / 16px | §3.1 和 `:root` 是 320 / 160 |
| §5.1 第 258、262–265 行 | 导航 200，可用宽 916，页标题高 48，主卡 916×约 340 | 916 = 1180 − 200 − 两侧留白，不是 1944 |
| §5.2 第 276、280–283 行 | 窄栏 96，可用宽 1020，题目列和提示列 y 112 到 748 | 748 = 820 − 72。1640 高的屏上没有这个底边 |
| §5.3 第 296、300–304 行 | 导航 200，可用宽 916，底栏高 96 | 宽仍是 916；§3.1 第 133 行底栏高是 120 |
| §5.4 第 318–319 行 | 节头 916×96，正文列宽 600，右侧栏在 x 624、宽 292 | 600 + 24 + 292 = 916 |
| §5.5 第 329、333–336 行 | 窄栏 96，视图条 1020×72，列区 1020 宽 | 1020 = 1180 − 96 − 两侧留白，不是 2104 |
| §5.6 第 348、353–354 行 | 导航 200，可用宽 916，两栏各 446 | 446 + 24 + 446 = 916 |

§5.2 第 285 行正文写「2360×1640 下」题干和「交这一题」要同屏，同一节表格的底边仍是 748。声明和区域尺寸对不上。

### 2.2 课本、章、知识点、测试、我的记录没有 2360 上的区域尺寸

§5.7 第 366–374 行给了五行尺寸。可用宽写成 1944。五行都没有内容区左上角为原点的 x、y，也没有在 1640 高里的底边。逐页对不上：

| 页面 | 位置 | 对不上的地方 |
|---|---|---|
| P-BOOK 课本 | §5.7 第 370 行 | 册卡写成「1944×至少 88」，章行只写高 88。高是下限，没有 y。v=39 的 `app.css` 第 397–399 行是 `.book-list { width: 720px }`、行 `min-height: 72px`，不是 1944×88 |
| P-CHAPTER 章 | §5.7 第 371 行 | 「左列约 1600，右栏 280」。约数不是尺寸；1600 + 280 = 1880，不到第 366 行的 1944，中间空档没有写。v=39 第 333–336 行是 `minmax(0, 1fr) 280px`，左列不是 1600 |
| P-KP 知识点 | §5.7 第 372 行 | 「整列最宽 1200，三列等分」。最宽是上限，没有高，没有 x、y。v=39 第 343 行是 `.kp-page { max-width: 880px }`，不是 1200 |
| P-TEST 测试 | §5.7 第 366、373 行，以及 §5.2 第 276、281 行 | 第 373 行写「与 P-PRACTICE 相同」，区域就还是可用宽 1020、y 112 到 748。第 366 行又写这五页可用宽 1944。§3.1 第 130–132 行把 P-TEST 放在窄栏，可用宽应是 2104。同一页同时是 1020、1944、2104。题号 88×88 只是方块，不是整页区域。v=39 第 519–520 行题号是 64×64 |
| P-RECORD 我的记录 | §5.7 第 374 行 | 只写「每张数字卡宽 360，高按内容」。章列表和导入导出没有宽和高。三张 360 的卡没有 x，也拼不出 1944。v=39 第 351–353 行是 `.record-page { max-width: 880px }`、`.stats .card { width: 240px }` |

严重：规定画布上仍没有这五页的区域尺寸，六页表格也没有改到 2360×1640。

## 3. 严重 2：最小字仍不是 44px

### 3.1 三处令牌已经是同一套

§2.2 第 75–82 行、§4.8 第 243–244 行、`prototype/app.css` `:root` 第 22–29 行，八个字号相同。最小档 `--fs-small` 是 44px。§0 第 16 行写明 264 ppi 上 12pt 等于 44px。按 44 × 72 / 264 = 12，这个换算成立。

| 令牌 | §2.2 | §4.8 | `:root` |
|---|---|---|---|
| `--fs-hero` | 88 | 88px | 88px |
| `--fs-h1` | 72 | 72px | 72px |
| `--fs-h2` | 64 | 64px | 64px |
| `--fs-h3` | 52 | 52px | 52px |
| `--fs-question` | 56 | 56px | 56px |
| `--fs-body` | 48 | 48px | 48px |
| `--fs-btn` | 48 | 48px | 48px |
| `--fs-small` | 44 | 44px | 44px |

上一轮 `:root` 里的 13px 已经不在这三处。这一条对上了。

### 3.2 孩子能看到的字仍有小于 44px 的规定

同一份规格在组件和页面里继续写更小的字。这些字给孩子看。44px 的令牌没有成为这一套字号。

| 位置 | 写的字号 | 264 ppi 上的物理大小 |
|---|---|---|
| §3.3 第 159 行，面包屑 | 16px | 4.4pt |
| §4.1 第 168–172 行，按钮和停用说明 | 20px、18px、16px | 5.5pt、4.9pt、4.4pt |
| §4.4 第 207–208 行，选项和填空 | 22px，原因 16px | 6.0pt、4.4pt |
| §5.1 第 262–263 行 | 页标题 30px；节名 44px；页码行 16px；说明 18px | 8.2pt、12pt、4.4pt、4.9pt |
| §5.2 第 281 行，题干 | 22px | 6.0pt |
| §5.5 第 339 行，全景文字 | 章名 20px，知识点名 16px | 5.5pt、4.4pt |
| §7 第 396 行 | 最小 44px，题干 56px | 与上表不是同一套 |

§2.2 第 75 行把节名定为 `--fs-hero` 88px，§5.1 第 263 行把同一节名写成 44px。§0 第 16 行和 §7 第 396 行把题干定为 56px，§4.4 第 207 行和 §5.2 第 281 行把题干写成 22px。§4.8 第 244 行 `--fs-btn` 是 48px，§4.1 第 168 行主按钮字是 20px。

v=39 的 `app.css` 第 354 行还有 `.stat { font-size: 28px; }`。`app.js` 第 1324–1326 行用它显示「我的记录」里的「交过」「正确率」。28 × 72 / 264 ≈ 7.6pt，不是 12pt。`:root` 的 44px 没有管住这行字。

严重：令牌三处对齐了，页面、组件和原型里孩子能看到的字仍小于 44px。

## 4. 判定

M6 不通过。

课本、章、知识点、测试、我的记录没有 2360×1640 上的区域尺寸；六页区域表仍写着 916、1020 和 y 到 748。字号令牌在 §2.2、§4.8 和 `:root` 是同一套 44px 起的阶梯，但规格正文和 `app.css` 第 354 行仍有更小的字。

本文件只复评上一轮的两条严重项。不宣布第一阶段通过，也不判定 M4、M5、M7、M8。
