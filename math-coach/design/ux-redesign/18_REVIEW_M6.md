# M6 视觉评审

- 负责人：独立视觉评审员（只评 M6）
- 版本：0.1
- 更新时间：2026-11-05 +08:00
- 关联：`08_DESIGN_SYSTEM.md`、`prototype/app.css` 的 `:root` 与文件前部 `.stage`、`.btn`
- 状态：不通过。只判定 M6，不表示第一阶段通过

## 0. 审什么

门禁：完整设计系统已经确定，全部主要页面已有对应的视觉设计规格。画布应为 iPad Air 11 英寸物理像素 2360×1640（文件写明 264 ppi）。

只读了两处：

- `design/ux-redesign/08_DESIGN_SYSTEM.md`
- `design/ux-redesign/prototype/app.css` 的 `:root`（第 1–46 行），以及紧接着的画布 `.stage`（第 56–62 行）和按钮 `.btn`（第 122–132 行）。`:root` 里没有画布和按钮高度，所以用文件前部这两处核对。

没有改代码，没有改设计稿，没有用浏览器点原型。下面每条都写文件位置。有严重问题则 M6 不通过。

## 1. 结论

**不通过。**

有两条严重问题：规定画布上没有主要页面的版面尺寸；字号没有收成一套，原型采用的那套在这块屏上孩子看不清。

## 2. 严重

### 严重 1：主要页面没有 2360×1640 的版面规格

`08_DESIGN_SYSTEM.md` §0 第 15–16 行和 §3.1 第 125 行把基准写成 2360×1640。`prototype/app.css` 第 56–62 行的 `.stage` 也是 `width: 2360px; height: 1640px`。画布声明两边一致。

页面版面没有跟着改。同一份规格仍按已经否定的 1180×820 写位置：

| 位置 | 写的是什么 |
|---|---|
| `08_DESIGN_SYSTEM.md` §5 第 254 行 | 「区域（基准 1180×820 下的位置和尺寸）」 |
| 同文件 §3.1 第 135 行 | 可视高度写成 `820 − 72 = 748`。1640 高的屏应是 1640 − 72 = 1568，文件里没有这个数 |
| 同文件 §3.1 第 129–132 行 | 标准导航宽 200、窄栏 96；内容区宽 980 / 1084，可用宽 916 / 1020。980 = 1180 − 200，1084 = 1180 − 96。2360 − 168 = 2192，文件里没有 |
| 同文件 §5.2 第 285 行 | 「1180×820 下」检查题干和「交这一题」是否同屏 |
| 同文件 §7 第 390 行 | 验收仍写「在 1180×820 下逐条手点」 |

§3.1 第 125 行正文写「左侧导航 168 宽」，同节表格却写 200 / 96。`prototype/app.css` 第 40–41 行是 `--nav-w: 168px`、`--nav-w-rail: 84px`，和表格的 200 / 96 也不一致。一节里有两个导航宽度，页面区域就无法落地。

六页有区域表，但坐标属于 1180×820，不能当作 2360×1640 的规格：

| 页面 | 位置 | 缺什么 |
|---|---|---|
| P-TODAY | §5.1 | 可用宽 916，页标题高 48，主卡约 340 高，都按旧画布 |
| P-PRACTICE | §5.2 | 题目列「y 112 到 748」，748 来自 820 − 72 |
| P-RESULT | §5.3 | 总结卡、列表、底栏都按 916 宽 |
| P-SECTION | §5.4 | 正文列 600、右侧栏 292，合计仍是 916 |
| P-MAP | §5.5 | 内容区 1020，视图条 1020×72 |
| P-REVIEW | §5.6 | 两栏各 446，间距 24，合计 916 |

另外五个主要页面没有自己的区域表：

| 页面 | 位置 | 有的内容 |
|---|---|---|
| P-TEST | §5.2 第 290 行 | 只写「用同一版面」，没有独立区域、尺寸和空状态块 |
| P-BOOK | §5.7 第 368 行 | 一行：一册一张卡，章行 72 高 |
| P-CHAPTER | §5.7 第 369 行 | 一行：骨架同节页，主按钮文案 |
| P-KP | §5.7 第 370 行 | 一行：正文列加右侧栏，主按钮文案 |
| P-RECORD | §5.7 第 371 行 | 三行：数字卡、章列表、空状态按钮，没有位置和尺寸 |

§5.7 第 366 行写明这四页「不在本次要求的六页之内」。导航里的课本、我的记录，以及章、知识点、测试，都是孩子会打开的主要页面。简要句子不是这块画布上的视觉规格。

严重：缺规定画布上的主要页面规格。

### 严重 2：字号有三套，原型那套孩子看不清

字号在三处各写各的。`prototype/app.css` `:root` 第 22–29 行跟 §2.2 的字号数字一致，跟「给原型用的变量清单」和页面正文不一致。

| 令牌 | §2.2 第 74–82 行 | §4.8 第 243–244 行 | 页面和组件里的字号 | `app.css` `:root` |
|---|---|---|---|---|
| `--fs-hero` | 28 / 34 | 44px | §5.1 节名 44px | 28px |
| `--fs-h1` | 20 / 26 | 30px | §5.1 页标题 30px | 20px |
| `--fs-h2` | 17 / 24 | 24px | §4.2 卡片标题 20 或 24px | 17px |
| `--fs-h3` | 15 / 22 | 20px | — | 15px |
| `--fs-question` | 16 / 26 | 22px | §4.4 选项 22px；§7 题干 22px | 16px |
| `--fs-body` | 15 / 22 | 18px | §5.1 说明 18px | 15px |
| `--fs-btn` | 15 / 22 | 20px | §4.1 主按钮字 20px | 15px |
| `--fs-small` | 13 / 18 | 16px | §7 第 393 行：孩子能看到的文字最小 16px | 13px |

§0 第 16 行和 §2.2 第 82 行把最小字定为 13px，并写「2360 宽的屏上 13px 仍可读」。§7 第 393 行仍要求最小 16px、题干 22px。同一份文件没有写以哪一套为准。

按文件自己的口径核对可读性：画布是物理像素，264 ppi，1px 当作 1 个物理像素（§0 第 15 行；`app.css` 第 55–58 行的注释也是这个意思）。

| 原型 `:root` | 物理大小 |
|---|---|
| 13px 辅助字 | 3.5pt，约 1.3mm |
| 15px 正文、按钮字 | 4.1pt，约 1.4mm |
| 16px 题干 | 4.4pt，约 1.5mm |
| 20px 页标题 | 5.5pt，约 1.9mm |
| 28px 节名 | 7.6pt，约 2.7mm |

儿童阅读常用大约 12pt。在 264 ppi 上，12pt 约等于 44 个物理像素。原型正文 15 个物理像素，大约是这个尺寸的三分之一。

若按平板真实的 2 倍点来看：视口是 1180×820 点，`.stage` 是 2360×1640 CSS 像素。要整页落在这块屏上，只能缩到大约一半，13px 仍是约 3.5pt。若不缩放，只能看到左上角，13 CSS 像素约 7.1pt，仍然偏小，而且右半屏和下半屏在视口外面。两种看法都是孩子看不清。

按钮高度也没有定死，和字号是同一类问题：§0 第 16 行写按钮高 40px；§4.1 第 168 行写主按钮高 60、字 20px；§4.8 第 248 行写 `--btn-h: 60px`。`app.css` `:root` 没有 `--btn-h`。文件前部 `.btn` 第 123 行是 `min-height: 40px`，字用 `--fs-btn`（15px）。40 个物理像素约 3.8mm，到不了手指能稳住的热区。§0 第 16 行写「仍大于手指最小热区」，和 §4.1 第 175 行「至少 44×44」互相矛盾，也和 264 ppi 对不上。

严重：令牌和原型对不上，采用的字号在规定画布上孩子看不清。

## 3. 没有升为严重的差异

这些对不上，但不单独构成「缺整页规格」或「因此看不清」。M6 已经由第 2 节否决。

### 3.1 间距

`08_DESIGN_SYSTEM.md` §2.3 第 90–98 行与 §4.8 第 245 行是一套。`prototype/app.css` 第 30–35 行是另一套，且没有 `--s-1`。

| 令牌 | 规格 | `app.css` `:root` |
|---|---|---|
| `--s-1` | 4px | 无 |
| `--s-2` | 8px | 6px |
| `--s-3` | 12px | 8px |
| `--s-4` | 16px | 10px |
| `--s-5` | 24px | 12px |
| `--s-6` | 32px | 16px |
| `--s-7` | 48px | 18px |

规格把 `--s-2` 定为两个可点目标的最小间距（§2.3 第 93 行）。原型把这个令牌写成 6px。这是令牌对不上。看不清已经由字号成立，间距不再单列一条严重。

### 3.2 圆角

§2.3 第 100–106 行和 §4.8 第 246 行有 `--r-sm: 8px`。`app.css` `:root` 第 36–39 行没有 `--r-sm`。`--r-md` 12px、`--r-lg` 16px、`--r-xl` 24px、`--r-pill` 999px 两边一致。

### 3.3 颜色

§2.1 第 39–55 行与 `app.css` 第 2–21 行，主色、背景、正文、对、错、看了答案、跳过、不稳、遮罩的色值一致。白字在 `#2F62E6` 上的对比约 5.24:1，与 §2.1 第 35 行「约 5.2:1」相符。次要字 `#5B6475` 在白底上约 5.96:1，与第 47 行「约 5.9:1」相符。

缺的和偏淡的：

- §2.1 第 53 行的 `--c-self: #6B4BD8`、`--c-self-soft: #F0ECFD` 在 `app.css` `:root` 里没有。「判不了」没有原型令牌。缺令牌不等于这行字已经消失，所以不升为严重。
- 「对了」的 `#17805A` 在 `#E6F5EE` 上约 4.37:1，低于正文常用的 4.5:1。两边色值相同，不是对不上。
- 「不稳」的 `#C46A00` 在白底上约 3.88:1。规格 §2.1 第 54 行把它用于小圆点和标题。两边色值相同。小字用这个橙色会偏淡，留在这里，不另立严重。

阴影三枚与 §2.3 第 110–112 行一致：`--shadow-card`、`--shadow-raise`、`--shadow-modal`。

### 3.4 字体栈

§2.2 第 66–68 行有 `--font-ui`、`--font-math`、`--font-num`。`app.css` 第 45 行只有 `--font-ui`，且顺序改成先「Microsoft YaHei UI」。没有数学字体令牌。本评审没有看符号是否被裁，不把这件事写成已经看不清。

## 4. 已经写上、并且两边一致的部分

- 色彩的主路径：主色、页面底、卡片、正文、对、错、看了答案、跳过、不稳、遮罩。位置：`08_DESIGN_SYSTEM.md` §2.1，`app.css` 第 2–21 行。
- 圆角的四档：12、16、24、999。位置：§2.3 第 103–106 行，`app.css` 第 36–39 行。
- 阴影三档。位置：§2.3 第 110–112 行，`app.css` 第 42–44 行。
- 画布像素数 2360×1640 的声明。位置：§0 第 15–16 行，`app.css` 第 57–58 行。声明一致，不能代替第 2 节里缺失的页面尺寸。

## 5. 判定

M6 不通过。

设计系统没有定成一套可执行的数：主要页面版面仍写在 1180×820 上，课本、章、知识点、测试、我的记录没有这块屏的区域规格；字号、按钮高度和间距各自至少有两套，原型用了更小的字号。按文件写明的 2360×1640、264 ppi，这套字孩子看不清。

本文件只判定 M6。不宣布第一阶段通过，也不判定 M4、M5、M7、M8。
