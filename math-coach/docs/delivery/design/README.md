# 画面设计目录

UX、交互、UI 共用这一处。任务卡若指定了别的目录，以任务卡为准。

| 文件 | 谁写 | 内容 |
|---|---|---|
| `flow.md` | UX | 屏幕编号、用户要完成的事、屏幕之间怎么走、对应哪份参考 |
| `interaction.md` | 交互 | 每屏的状态、操作、跳转、反馈，以及这个状态要不要一张图 |
| `layout.md` | UI | 每张图的路径、屏幕编号、状态、对照的参考、图上各区域是什么 |
| `screens/` | 谁出图谁放 | 大致布局或流程粗图。文件名带屏幕编号 |

三个人都不改对方的文件，也不派发对方。图和文档对不上时写进汇报，由主会话决定退回谁。

UI 没有图片文件，就不算界面已经设计出来。UX 的 `flow.md` 和交互的 `interaction.md` 仍然要交；出不了粗图或草图时在汇报里说明，不把整个任务停掉。

主会话按这次任务选模型。产品、架构、UX、交互优先用当前可用的顶尖模型；UI 必须能调用生图工具。开发和 QA 默认跟随主会话。指定模型没有额度时退回默认模型：Cursor 把该成员的 `model` 改回 `inherit`，DeepSeek 改用任务卡里的 `fallback_model`，不要省略。UI 的回退模型也必须能出图。

这里还不放图。底层数据仍在 `content/`，现有界面仍在 `runtime/web/`。正式让 UI 开画之前，先用能出图的模型做一次只出一张草图的 Canary。
