# 界面与架构：诊断、已改、还欠什么

> **状态（2026-10-28 复核）**：已被 `docs/plan/2026-10-28-ux-overview-redesign.md` 与 `docs/plan/2026-10-28-competitor-parity.md` 取代。本文列的「217 道选择题在界面上不可点」已解决（200 道可点选）；「539 道必图题没有图」仍未解决。


用户反馈原话是「图谱界面太简陋、色彩单调、不高级，要优美可扩展、眼前一亮」。这份文档记录三份专家报告与我的实测结论、本轮已落地的改动，以及按优先级排的剩余工作与验收标准。数字均为实测，不是估计。

## 一、诊断：挡住日常使用的不是「不好看」

产品、UX、架构三方独立盘点后结论一致：视觉是第二位，第一位是三处功能断点。

1. **217 道选择题在界面上不可点。** `content/questions/801/` 下 `options` 字段出现的次数是 0，选项文本以换行留在 `stem` 里；判题侧输入正确字母 → correct 14 / manual 203 / wrong 0。
2. **539 道必图题（`need=required`，占 2642 题的 20%）既没有图也没有文字替代。** 12.5「全等判定」一节 73/85 = 86% 必图。源数据每条都带 `figure.reason` 与 `figure.hint`，只是没进运行时分片。
3. **七屏设计里的「测 / 补 / 复习」在代码里不存在。** `router.view` 只注册了 today / toc / sec / kp / map / practice / archive。

「不高级」的可测根因（针对改前 v1 样式）：间距出现 18 个离散值（含 7/9/11/14/15/18/22px，并非自称的 4 的倍数）；字号 16 档但字重只有 400/600 两档；整份 CSS 只有 2 处 `box-shadow`、0 处 `@keyframes`、0 处深色模式；`--maxw: 760px` 被顶栏、正文、底栏、抽屉共用，桌面就是一列手机版。对比度也不达标：`--ink-mute #8b969f` 在纸白上 2.89:1（AA 需 4.5）。

图谱页另有一个硬伤：按各视角节点盒尺寸复算，**节点总面积是手机画布面积的 3.4–7.6 倍**，而 `MIN_ZOOM=0.5` 把下限硬抬起来，结果一屏只见四分之一张图，且没有小地图、没有面包屑、没有搜索定位。

## 二、已改（三轮，均已进闸门）

**R1 设计系统。** `runtime/web/app.css` 从 227 行重写到约 600 行：完整 token 体系（中性 8 级、五档难度色、三域色、语义色）、整套深色模式、阴影三档、圆角四档、字阶八档、动效两档并全部包 `prefers-reduced-motion`、`:focus-visible` 焦点环、点阵纹理画布、宽屏（≥1024px）左侧固定导航 + 880px 正文上限。

**R2 图谱页结构重做。** `map.js` 整份重写（949 行），三个决定值得记下来：

- **放弃 dagre / 力导向，改手算 preset 坐标。** DAG 的层序是资产不是负担：孩子第二次打开必须看到同一张图。骨架视角一章一岛（桌面四章并排、窄屏一列靠拖动翻章），其它视角一节一岛。
- **相机「看得清」优先于「看得全」。** 窄屏骨架不 fit 全图（fit 会把 11.5px 的字压到 4px，等于没字），改按宽度定倍率并停到第一个岛；想看全景点「看全」。
- **两个隐形坑。** ① 只传自定义 style 时 cytoscape 不再套默认 `label:'data(label)'`，表现是「框全画出来、一个字也没有」，必须显式声明；② `min-zoomed-font-size` 会在 zoom 偏小时把全部文字隐藏，症状与 ① 一模一样。两条都已修，并写进代码注释。

另外：边按 confidence 区分（人工确认的先修是墨绿加粗，规则推出来的细淡），「哪些是推断」看得见；节点盒加宽（节 178 / 知识点 140），节标题保留「10.1 」序号；画布内浮层搜索与图例；配色全部从 CSS 变量读，深色模式跟着变。

**R3 首页信息密度。** `today.js` 重写：四格状态带（今天 / 近 7 天 / 连续天数 / 待改题数）、**「我在学哪一节」下拉**（写 `mc.settings.v1`，推荐逻辑改为优先用它 —— 原来推荐永远从字符串最小的节开始，孩子改不了）、主卡带「这一节做过几道」、**待改的题**（从作答记录派生：最后状态是错/没做且之后没做对过，最多列 3 条，一键回去改）、近七天柱状带数值。

顺手修掉三处体验断点：题干 `white-space:pre-wrap`（选项 A./B./C./D. 不再挤成一行）；来源与难度徽章撞车时去重（原来会并排出现两个「基础」）；换屏复位到顶部并加 160ms 淡入（原来从两千像素高的节页滚到底再点「开始练」，进来先看到半张卡和一片空白）。

验证：`bash tools/check_all.sh --web` 失败步骤 0，无头冒烟 **19/19 PASS**；截图见 `out/shots/web-map-desk.png`、`web-today-data.png`、`web-map.png`。

## 四、架构补项（不进界面，但决定能不能用）

1. **`runtime/web/data/` 在 `.gitignore` 里，`git ls-files` 命中 0。** 直接发布到 Pages 就是全站 404。要么把派生产物改成构建期生成（推荐，Pages 上跑一次 `build_web.py`），要么单独提交一份产物。
2. **发布前必须有泄漏闸门。** 4–5★ 含真题成分的题标着 `visibility=stem_public` / `redistributable=false`，cite-only 内容也在库里。现在没有任何脚本在发布路径上拦它们。
3. **首屏 404.8KB 未压缩，其中 `katex.min.js` 269KB 占 66%。** 非数学页用不到。按路由懒加载即可，gzip 后实际传输只有 0.09MB，不是瓶颈但能省。
4. **待纠错目前是「从记录派生」而不是独立实体。** 够用，但跨设备同步（M4a 之后）需要能合并的队列。
5. **搜索要别名层，不是加个输入框。** 知识点标题中位 27 字、52% 含冒号（「名称：一长串定义」），纯子串检索的假阳性会很严重。

## 五、两个需要拍板的点

1. **这一轮要不要动公开部署？** 涉及泄漏闸门与派生产物是否入库两件事，动就要先做上面第 1、2 条。
2. **「不高级」主要指图谱页还是全站？** 已按「图谱页为主、首页其次」做了 R2/R3；如果其实指的是手机整体观感，下一轮就先做 E5（离线可安装）+ R4（视觉二次收敛）。

## 六、图谱页第二轮（配色 / 讲解 / 例题）

用户反馈三条：不如旧工程清晰；前置、后置、关联方法、思想方法、知识点说明、例题都没解释；整体偏淡不够明亮。

**配色**：纸色从暖砂纸 `#f7f4ee` 换成冷白 `#f1f6fb`；正文墨色 `#0c1a24`；弱化色从 `#8a938d`（对比度 2.89:1）提到 `#63758a`；三域色（代数蓝 `#1a63cf` / 几何绿 `#0a7d5a` / 统计紫 `#8b2fbd`）与五档色整体提饱和；岛底不再整块铺淡色，改成 5% 域色 + 30% 边线；非邻域节点透明度从 0.14 提到 0.58（0.14 时整片变成灰点子，看着像没加载完）。

**讲解**：右栏改成固定六段——定义/成立条件/容易混/要能做到 → 前后关系（直接邻居 + 折叠的多跳链路，标跳数、可点跳转）→ 配的方法（步骤带依据）→ 常踩的坑 → 课本例题（ex 数据片，答案折叠）→ 这一节的题（答案折叠）。宽度 404px，≥1080px 时 sticky 贴着图。

**修掉三个「把已有信息抹平」的 bug**：关系按钮把名字裁到 24 字（现在写全，允许两行）；题卡先 `plain` 再 `mathHtml`，把 `$\frac{1}{x}$` 抹成「1x」；方法的「容易犯的错」取的是图节点而不是节数据里的错因记录，于是三条全叫「这类错法」。

**仍然缺的（内容，不是界面）**：

1. **思想方法族没有数据。** 旧仓有 M-SYN/MET/ANA/INV/EXT/COM 六族 25 法 97 技法的双轴，新仓 `content/skills` 只有 `tier`（教材/培优/竞赛）。要在讲解里写「这个方法属于转化与化归」，得先给 skill 加 `family` 字段并人工标注，界面到时候直接读。
2. **题库只有 12 章标了考点**（`content/questions/801/ch12.kp.jsonl`，243 条映射指向 38 个知识点）。10/11/13 章的题 `kps` 是空数组，所以「这一点的题」在本节点没有关联题时退回「这一节的题」，小标题写明是本节，不假装精确。补 10 章 73 道题的映射用 `tools/questions_kp_writeback.py` 半自动跑，属内容任务。
3. **教材题的例题与练习还没分桶。** ex 片与 items 片都按节存，讲解里优先取 ex，但「例题」与「习题」在数据上没有额外标记（只有 `src` 里的「教材巩固/提升/拓展」）。
