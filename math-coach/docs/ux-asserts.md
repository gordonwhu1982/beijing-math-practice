# 视觉断言（tools/ux_asserts.js）

这道门的由来：反复出现的那句「**改了显示还是有问题**」。
冒烟（`web_smoke.js`）判的是「文案在不在、公式渲染没渲染、有没有横向溢出」，
它看不见「字小得费眼」「内部英文枚举漏到界面」「公式被劈成两行」「首屏没有主按钮」。
这几类都不报错，只会让人反复返工，所以单独一道门：**能量出来的都量，量完给退出码**。

```bash
node tools/ux_asserts.js                      # 430 全量 18 条路由 + 1280 复跑 8 条
node tools/ux_asserts.js --json out/x.json    # 顺带存度量
node tools/ux_asserts.js --shots out/shots/x  # 同一套路由出全页图（2x，直接看；today 两个状态各一张）
W=860 node tools/ux_asserts.js                # 只跑一档宽度
node tools/ux_asserts.js --only today         # 只跑指定路由（调一屏时别等全量）
node tools/preview_seeded_today.js            # 造一份「真的做过题」的记录并出 today 全页图
```

退出码 = 不达标条数（全过为 0）。**判据分两类**：静态的（字号、枚举、折行、溢出、几何）与交互的（点一下看有没有反应）。只做前者会漏掉「页面看着对、其实点不动」——2026-10-31 就是这样漏了一个整屏的死交互。钩子在暂存命中前端时自动跑它；
`bash tools/check_all.sh --web` 第一步就是它。

## 判据与阈值

| 判据 | 阈值 | 为什么是这个数 |
| --- | --- | --- |
| 小字占比 | < 13px 的可见字符 ≤ **5%** | 字号下限已在 `app.css` 抬到 `--fs-xs:13px`；这条防回归。改前实测 47.8% |
| 最小档占比 | **≤13px** 的字符占比 ≤ **30%** | 这条才是真正在管「字小」。13px 是合法的最小档，所以上一条的 `fs2 < 13` 永远不命中它：kp 屏 65%、map 屏 61% 的可见字是 13px，门却一直报 `small=0.0%`（2026-10-31 设计评审抓出来的创业板）。留 30% 余量给标签：题号胶囊、pill、折叠摘要 |

### today 是**三**态测量，少测一态就漏

同一个 today 页要测三次，每次 reload 前换掉 localStorage：

1. **首次态**（空记录）：必须先问「你在学哪一节」，提问卡在首屏（≤200px），而且**不给主按钮**——
   先回答问题再谈练什么。
2. **用户态**（`{current:'11.1',picked:true}`，仍无记录）：提问卡必须消失，主按钮 ≤260px。
3. **有记录态**（再注入 12 条作答记录）：主按钮仍 ≤260px，且「还欠着的题」「该抽回来看看」
   每一行都得回填出题干；据此还能判 `hint` 全是 `none` 时不许出现「带提示」。

测完把 `mc.settings.v1` 与 `mc.records.v1` 都清掉，后面的路由从同一起点开始。

### archive / weak / retry 要先喂数据（`SEED_ROUTES`）

这三页默认是空库：`.statgrid` 不渲染、列表只有一句「还没做过」。第一版「统计合计」判据
就因为 `statSum` 恒为 `null` 而**永远不会触发**（判据自己是绿的，页面是坏的）。
所以跑这三条路由前先注入 8 条记录的 `SEED_RICH`（错/对/跳过/空卷/判不了各有），
量完立刻 `localStorage.removeItem` 还原。**新的页面级判据都要问一句：这条路由默认有数据吗？**
没有就先造，否则等于没写。
只测首次态会漏「老用户被提问卡拦路」，只测用户态会漏「新用户不知道该选哪节」，
只测前两态会漏掉「真的做了题」这第三种 —— 而它才是日常的样子。
三态各出一张图（`M430-today.png` / `M430-today-user.png` / `M430-today-seeded.png`），
数字和眼睛一起看；`preview_seeded_today.js` 专门出第三张。

阈值写在本文件顶部常量里。**改阈值就是改验收标准**，改完要在 `docs/STATE.md` §7 写为什么。

## 两条判据的现场教训（别再犯）

1. **主按钮按类名找，不按颜色找。** 早期版本写 `rgb(10, 125, 90)`，后来 `--green` 改成 `#097756`，
   这条断言恒判达标 —— 等于不存在。凡断言依赖具体色值，就等着被一次调色废掉。
2. **小字统计要排除公式内部与零宽字符。** KaTeX 的上标是 `0.7em` 的 scriptstyle（排版规范，
   不是界面字小），`1px` 的零宽字符承载元素没有度量意义。不排除就会得到一堆假失败，
   然后人就学会忽略这道门。

## 枚举词表是数据驱动的

`tools/enum_values.json` 由 `python tools/enum_scan.py` 生成：把 `content/` 里
**作为字段值出现的短英文串**收成词表（当前 169 个）。断言拿它去扫界面文本节点，
命中即失败，并打印「哪个元素在漏 + 前后文」，方便直接定位渲染点。

为什么不用手写清单：早期手写了 9 个词，结果 `prerequisite_missing`/`representation` 漏了一整类。
词表跟着数据走，新加一类枚举自动进检查范围。数据改了记得重跑 `enum_scan.py`。

## 和冒烟的分工

| | 冒烟 `web_smoke.js` | 视觉断言 `ux_asserts.js` |
| --- | --- | --- |
| 判什么 | 该出现的文案在不在、点得动点不动、几何不重叠 | 字够不够大、有没有漏英文、公式有没有被劈、首屏有没有主按钮、首屏动作在不在 |
| 断言数 | 62 条 | 38 个判据代号（每个 `f.push` 的前缀就是一档，`grep -o "f.push('[A-Z]*" tools/ux_asserts.js` 可复算）+ 2 类资源（KaTeX 样式表 / cytoscape 真的加载）+ 1 类交互 × 29 次路由（430 宽 19 + 1280 宽 10；today 另测三态；archive/weak/retry 另注入 `SEED_RICH` 8 条记录；`kp-bad` 专测死胡同；`practice-look` 专测单题预览态能不能自己答） |
| 失败意味着 | 功能坏了 | 功能没坏但看着不对 |

**同一档在两遍视口里形态可以不同，断的事必须一样。** 例：`#/map` 在 430 宽是 DOM 章列表（画布缩到 0.37 倍时 13px 的字只剩 4.8px），在 1280 宽是章级卡片画布；`map` 路由的期望文案因此只取两边都成立的三件事（是不是章级全景、有没有「知识点」、是不是「章」）。形态差异要写在路由注释里，别让下一个人以为某一遍漏了。

两个都在钩子与 `check_all --web` 里，都需要本机 Chrome（`MC_CHROME` 可改路径）。
环境不就绪**算失败不算跳过**：跑不了等于这道门不存在。
