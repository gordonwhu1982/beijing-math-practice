# 错题重练：欠着的题一次做完（`#/retry`）

## 为什么要有这一页

今日页「还欠着的题」原来每行只给一个「回去改」链接，点进去跳回那一节；练习页的队列重排只在**同一节内**把答错的题重新插回队尾。跨节的错题因此没有出口——孩子错了 5 道、分属 3 节，只能一节一节点进去，进去还不一定先遇到那道错题。

这一页把「欠着」当成一个跨节的集合来读：先摊开讲清楚欠了多少、欠在哪几节，再给一个开始键。

## 「欠着」的口径（与今日页完全一致）

这道题**最后一次作答是 `wrong` 或 `blank`，且此后没有 `correct`**。判定只看 `MC.store` 里的作答事件流，按 `item` 归并取最后一条；做对一次就从队列消失（不区分是谁做对的）。

## 行为

- 顶部「一次做完 N 道」：排 **6 道**（按最后作答时间从近到远），做完一题继续下一题，与普通练习同一套渲染、同一套判题。
- 每行「只做这道」：只把那一题排进队列。
- 混合队列**不再按难度配额挑题**（普通练习会平衡 basic / standard / advanced）。挑剩下就等于把错题绕过去。仍然剔除两类：选择题但选项原文没抽出来、必须配图却缺图说明；页脚写「这一批还有 N 道」。
- 判不了的题（解答题为主）照常排进来，交卷后落 `manual`，四行卡给出「卡在哪 / 先得会 / 做法 / 回到图上」。

## 实现要点

- `runtime/web/js/views/retry.js`：`pending()` / `enrich()` / 列表渲染。用 `host.onclick = ` 而不是 `addEventListener`——本仓已经两次踩过监听叠加导致一次点击跑多遍。
- `runtime/web/js/views/practice.js`：新增 `startMixed(list)` 与 `S.mixed`；新增四个 helper `itVol / itSec / itSecTitle / itCh` 统一回答「这道题在哪一节」。练习切片的 item 里**没有** `vol`/`sec`/`chapter` 字段（`tools/build_web.py` 不写），混合队列在前端注入 `_vol / _sec / _secTitle / _ch`。
- `record()` 的 `sec` / `volume` / `chapter` 改走 helper：混合模式下 `S.sec` 是 null，原实现会崩。
- 小结页的「再来一组」在混合模式下改成「还有欠着的题（#/retry）」，避免把整批重开一遍。

## 闸门

`tools/web_smoke.js` 的 `retry-mixed`：造 4 条真实错题记录（挑**相距最远的两节各两题**——题库只有 801 有题，写死节号会在无题节上静默变成 0 条）→ 进 `#/retry` 断言 4 行与「一次做完 4 道」→ 点它断言页头「第 1 / 4 题」且有作答控件 → 清掉探针记录。

## 已知边界

- **按题归并，不按知识点**：同一知识点错 3 道题会排 3 次。想按知识点归并，得先有「题 → 知识点」映射；现在全库只有第 12 章的 243 条，alias 子串匹配那条路已证伪（与人工映射吻合率 55%）。
- **队列上限 6**：一次排太多会变成惩罚。第 7 道之后下次再进。
