## 1. 要复刻的 9 条视觉手法

每条格式：**竞品在哪一屏哪个位置** → **我们要复刻的东西** → **证据等级** → **我们现在**（只对照，不提改法）。

### V1 漏斗式筛选栏：两位序号 + 计数角标 + 一句范围说明
竞品：`t02` 左中右三栏的**标题行**——「01 核心素养 6 ／ 可多选·符合任一项」「02 教材 5 ／ 选择一本教材」「03 章节 …／点击章节展开」；序号是浅绿小字（01/02/03），层名黑色粗体，计数是紧贴层名的浅灰小号数字；每栏**底部**还有一行 10–12 字灰字（「教材目录顺序」「点击章节展开右侧」「前后置可进入局部图」）。同一套编号延续到 `t03`（03 章节 5、04 知识点 35）与 `t04`（05 解题方法 9）。
复刻：任何一层列表/筛选，标题行必须是「两位序号 + 层名 + 本层数量」，副行一句「这一栏现在是什么范围」；顶部另有一行面包屑式路径（竞品写「素养 → 教材 → 章节 → 知识 → 方法」）。
证据：**【图上看过】**（t02/t03/t04 三帧同一形态）。
我们：没有任何序号或层计数——`runtime/web/app.css:493` `.mapbar` 只是横向 flex 放的几个 `select`；路径感靠 `#topbar .sub`（app.css:129）。

### V2 列表卡右对齐的数字：一张卡必须能回答「它有多少」
竞品：`t02` 素养「数学抽象 378」「逻辑推理 420」「数据分析 83」，教材「必修第一册 113 个知识点」；`t03` 章卡右边缘一列 35/29/14/8/27（合计 113，与册计数自洽）；`t04` 方法卡第二行「2 个知识点联系」。
复刻：每张列表卡都带一个**可横向比较的数字**，位置固定在右侧（或第二行），字号比标题小、颜色浅一档；数字列要能连成一条竖线。
证据：**【图上看过】**。
我们：册行有（`toc.js:67` 输出「N 节 · 知识点 M · 题 K」），**章卡只有题数**（`toc.js:81-82`「N 题／暂无题」），没有知识点数；卡片结构 `.kp-card .h .nm{flex:1}`（app.css:427）把标题撑满，没给右侧数字留位。

### V3 选中态只有一种编码：同族浅底 + 1px 同族细边
竞品：`t02` 选中的「必修第一册」「直观想象」是浅蓝底 + 蓝细边；`t03` 选中章「第1章 集合与逻辑」是浅绿底 + 深绿边，选中知识点「元素与集合的关系」是浅蓝底 + 蓝边。三处都没有阴影、没有加粗、没有实心填充。
复刻：全站「选中」用同一套语言：类型色 soft 底 + 同族 1px 边；禁止用实心填充表达选中（实心只用于「主按钮」）。
证据：**【图上看过】**。
我们：三种并存——`.chip.on{background:var(--green);color:#fff}`（app.css:267，实心）、`.layer-card.on`（app.css:891，浅绿底描边）、`.dd-count.on`（app.css:899，浅绿底描边）。

### V4 多层列表之间只画「当前那一条」连线
竞品：`t03` 章卡「第1章」右缘一个小圆点，引出一条**橙金色细曲线**，落到右栏选中的「元素与集合的关系」；其余卡只有灰色小圆点，不连线。`t02` 同法：从被选中的「直观想象」引出数条细弧到右栏各册卡（这里连的是全部，因为是多对多）。
复刻：跨栏联动只允许「选中项之间一条高亮线」，颜色用强调色（我们已有金色 `#c48a12`，app.css:938 在用）；不加箭头、不加动画。
证据：**【图上看过】**。
我们：多层列表形态还没有（`#/toc` 是单列上下排，`#/map` 是画布），所以这条是「新增形态时要守的规矩」。

### V5 边语义：一屏一句话，位置固定在图正下方
竞品：`t04` 右下角一行「**实线：解题可用·虚线：使用知识**」，紧贴方法列表下方、同一水平线；`t08` 底行「前置准备 → 当前知识 → 后续知识」是同一位置上的另一句。两处都在「图的边缘一行」，不浮动、不折叠。
复刻：图例固定在图的同一条边（我们取正下方），**内容随视图变，位置永不变**；「实线/虚线」两个词的含义跨视图不许变。
证据：**【图上看过】**（t04 的图例文字确实可读）+【OCR文本】（原文「实线：解题可用」「虚线：使用知识」，analysis:142）。
我们：有，但分散——`LEGEND` 7 组（`map.js:105-140`），两义只在 skill 视图出现（`map.js:128-131`「实线：这个方法能解这些点」「虚线：讲这个点时要用到它」），overview/chart/skeleton/kp 四视图的图例讲的是「这一层是什么」而不是边语义。

### V6 详情面板：顶部 tab 带计数 + 类型胶囊 + 标题竖条 + 分块右上角一句「这块是什么」
竞品：`t05/t06` 顶部一行「当前 ｜ 前置 0 ｜ 后续 0 ｜ 应用 7」，当前项底下一条**黑色粗下划线**，其余灰字；下面一排胶囊「当前」（蓝边浅蓝底）+「● 解题方法」（紫点 + 紫边浅紫底）；标题「坐标法处理几何问题」左侧一条**深蓝竖条**；`m09` 每个分块的标题右侧一行更小的灰字解释字段用途——「◆ 解题方法 … 方法 ▶ 体现的思想」「▲ 数学思想 … 背后的想法」「● 核心素养 … 培养方向」「■ 教材位置 … 课本编排」，最末「→ 接下来可以学」。
复刻：①详情面板第一行是可点的**计数 tab**（不是纯文字统计）；②实体类型用胶囊（色点 + 浅底 + 同色边）；③分块标题必须带一句 ≤8 字的「这块是干什么的」。
证据：**【图上看过】**。
我们：②③已有雏形——`.dd-block>h3 em`（app.css:670）就是那句解释、`.dd-cp` 素养段「名称靠左、条数靠右」（app.css:748-753）；①没有：计数是 `.dd-counts`（app.css:892-900）一排按钮，但不在「顶部 tab」位置，且不是页签语义。

### V7 形状 + 颜色双通道：同一个实体在图上、图例里、详情里用同一个形状
竞品：`m01` 左侧竖排 8 行图例，每行是「形状+颜色 → 名称」：紫红圆点＝核心素养、蓝点＝教材、绿点＝章节、灰＝课节·课时、橙黄＝知识主题、蓝＝知识点、紫＝应用能力、**黄三角＝数学思想**（画布上方六个黄三角岛就是它）；`m09` 分块标题前用同一套形状字符（◆ ▲ ● ■ →）。也就是说：形状不是装饰，是第二编码通道。
复刻：实体类型必须同时有形状与颜色，且**图例、画布节点、详情块标题三处形状一致**；颜色撞车时靠形状兜底。
证据：**【图上看过】**（m01 图例与岛、m09 块标题）。
我们：图例只有颜色——`.legend .sw{width:9px;height:9px;border-radius:3px}`（app.css:406-407），一律小方块；画布里知识点是菱形、章是方块（`map.js` 画布绘制），但列表与图例不复用。

### V8 一屏一个主动作，主动作在最下/最右，其余降级为文字链
竞品：`m05` 思想详情卡最底部只有**一个**深色实心按钮「阅读完整内容」；`m03` 一屏的主动作是顶部那行筛选胶囊（选中「情境」是深色填充）；`t02` 干脆没有主按钮——它是查找型界面。
复刻：任一屏 `.btn-primary` 恰好 1 个；次要动作一律 `.btn-ghost` 或带下划线的文字链。
证据：**【图上看过】**（m05/m03）+【我的知识，未验证】（「恰好 1 个」是我给的量化口径，竞品没有这条规则文本）。
我们：源码层面主按钮偏多——`map.js` 6 处、`practice.js` 3 处、`section.js`/`weak.js`/`archive.js`/`retry.js` 各 2 处（同一屏是否同现需运行时数，见 L5）。

### V9 图的读法写成一句口诀，而不是一行数据
竞品：`m06` 一张信息卡——左侧大字「**上下是归属，左右是先后**」，右侧一张界面小图，下面三行小字注解；`m07` 同版式「**边读详解，图谱不离场**」，小字「详情在右，知识链与图谱保留在界面」。八个字说清编码，其余全是注解。
复刻：图上方/下方给一句 8–12 字的口诀（一句一件：归属/先后、或读法/位置），数据统计（N 点 M 边）降到第二行小字。
证据：**【图上看过】**（两张卡片的版式与文字）。
我们：口诀已经有了，但埋在说明区——`map.js:142-144` `LEAD.overview`「上下是归属（章属于册），左右是先后（册与册的顺序）」；孩子第一眼看到的是 `paintNote()` 打的句子「现在这张图：N 个点 · M 个岛 · K 条关系」（`map.js:4369-4376`），先报数、后讲读法。

## 2. 验收项（16 条，可勾选）

判定方式两种：**脚本**（在目标页面的 DevTools console 里粘一行，返回 `true` 才算过）与**人眼**（写明看哪个元素的哪个属性，不写「看着舒服」）。
屏名用真路由：`#/today` `#/toc` `#/toc/801` `#/sec/801/12.5` `#/kp/<kid>` `#/map` `#/map?vol=801` `#/practice/801/12.5` `#/rel/<kid>` `#/weak` `#/archive` `#/evidence` `#/retry`。

### 2.1 布局与层级（L1–L6）

- [ ] **L1 宽屏两栏不塌** — 屏：`#/map?vol=801`（窗口 ≥1080px）；位置：画布与讲解；应看到：图在左、讲解固定 404px 在右，两者并排且各自可滚。判定：脚本 `getComputedStyle(document.querySelector('.mapwrap')).gridTemplateColumns` 返回值以 `404px` 结尾，且 `document.querySelector('#map-detail').getBoundingClientRect().width` 在 403–405 之间。
- [ ] **L2 每层列表都有「序号 + 层名 + 数量」标题行** — 屏：`#/map`、`#/toc/801`；位置：每个筛选/列表栏的标题行；应看到：形如「03 章节 5」的三段式，序号为两位数字、计数量随数据变。判定：人眼看每栏标题首字起第 1–2 个字符是两位数字且颜色为浅色（非 `--ink`），标题行内另有一个数字等于该栏条目数。
- [ ] **L3 列表卡的数字列对齐** — 屏：`#/toc/801`（章行）与 `#/map?vol=801` 的详情列表；位置：每行右端的数字；应看到：所有数字右端或左端对齐在同一竖线。判定：脚本取各行数字元素 `getBoundingClientRect().right`，`Math.max-Math.min <= 2`。
- [ ] **L4 分块标题都带 ≤8 字用途说明** — 屏：`#/map?vol=801`（打开任一知识讲解）、`#/kp/<kid>`；位置：每个块标题右侧；应看到：一行更浅更小的字，说这段是什么。判定：脚本 `[...document.querySelectorAll('.dd-block>h3 em')]` 非空，且 `every(e=>e.textContent.trim().length>0 && e.textContent.trim().length<=8)`；同时块标题总数与 em 数量相等（覆盖率 100%）。
- [ ] **L5 一屏只一个主动作** — 屏：`#/today`、`#/sec/801/12.5`、`#/archive`、`#/practice/801/12.5`（各自静止态）；应看到：每屏只有 1 个实心主按钮，其余是描边或文字链。判定：脚本 `document.querySelectorAll('.btn-primary').length === 1`，四屏分别执行。
- [ ] **L6 层级不靠字号靠字重与颜色** — 屏：`#/kp/<kid>`；位置：块标题 / 小标题 / 正文三级；应看到：三级字号接近（不靠放大标题压人），靠字重与灰阶分档。判定：脚本分别取 `.dd-block>h3`、`.dd-col>h4`、`.dd-block p` 的 `fontSize`，相邻两级差值 ≤ 1px；同时 `fontWeight` 相邻两级差值 ≥ 150，且颜色三者互不相同。

### 2.2 色彩与对比（C1–C5）

- [ ] **C1 选中态只有一种语言** — 屏：`#/toc/801`、`#/map?vol=801`、`#/sec/801/12.5`；应看到：所有「已选中」元素都是「浅底 + 同族 1px 边」，没有实心填充的选中项。判定：脚本收集 `.chip.on, .layer-card.on, .dd-count.on, #tabs a.on`，统计其中 `getComputedStyle(el).color === 'rgb(255, 255, 255)'` 的数量（反白字＝实心编码），要求 ≤ 1。当前 `.chip.on{background:var(--green);color:#fff}`（app.css:267）会命中，浅底描边的选中项文字是类型深色、不会。
- [ ] **C2 所有列表数字等宽** — 屏：`#/toc/801`、`#/map?vol=801` 详情、`#/archive`；应看到：数字不因字形宽度跳动。判定：脚本对每屏所有含纯数字文本的元素检查 `getComputedStyle(el).fontVariantNumeric === 'tabular-nums'`，覆盖率 ≥ 90%（现状：`.wk-n` app.css:1007 与 `.stat .n` 已设，列表行未设；留 10% 余量给日期之类的非比较性数字）。
- [ ] **C3 正文与辅助文字对比度达标** — 屏：任一带正文的页面；应看到：正文深、辅助浅但可读。判定：脚本按 WCAG 公式算 `--ink`/正文底色、`--ink-soft`、`--ink-faint` 三组，均 ≥ 4.5:1。**实测现状（2026-10-30 计算）**：16.40 / 7.10 / 4.87 —— 三组均过。
- [ ] **C4 类型色两两可区分** — 屏：`#/map?vol=801` 画布图例；应看到：任意两种代表不同含义的颜色，肉眼一眼分得开。判定：对 `--basic --standard --advanced --challenge --competition --dom-num --dom-geo --dom-sta` 八色两两算 CIEDE2000，要求最小 ≥ 10。**实测现状：最小 3.9**（`--basic #0a7a63` vs `--dom-geo #0a7d5a`），另有两对 4.4（`--competition #7433c4` vs `--dom-sta #8b2fbd`）、5.8（`--standard #2554d6` vs `--dom-num #1a63cf`）—— 未通过。
- [ ] **C5 同屏边框颜色不超过 2 种** — 屏：`#/map?vol=801`（含讲解）；应看到：卡片边、选中边、分隔线加起来只有两档灰。判定：脚本统计同屏所有可见元素的 `borderColor` 去重数量 ≤ 2。现状：`.card` 用 `--line #c3d3e3`、`.chip` 用类型色、`.dd-count.on` 用 `--green`，至少 3 种。

### 2.3 图谱与交互（G1–G5）

- [ ] **G1 同一路由两次打开，节点位置完全相同** — 屏：`#/map?vol=801`；应看到：刷新后每个点的位置不挪。判定：脚本 `JSON.stringify(cy.nodes().map(n=>[n.id(),Math.round(n.position().x),Math.round(n.position().y)]))` 在两次独立打开（含一次强刷）后字符串相等。依据 STATE 决策 11「每次打开位置必须相同，不用 Math.random」。
- [ ] **G2 图例位置固定在图的正下方一行** — 屏：`#/map`、`#/map?vol=801`；应看到：无论切哪个视图，图例都在图的同一条边、同一行高。判定：脚本取 `#map-legend` 与 `.mapstage` 的 `getBoundingClientRect()`，要求 `legend.top - stage.bottom` 在 −4…+12px 之间，且切换视图后该差值变化 ≤ 4px。

## 3. 不该抄的（5 条 + 1 条低优先）

每条的「不抄」都是 STATE 已定案的，不是本文新提的；这里只是把理由写在验收尺子旁边，避免执行时被推翻。

1. **力导向布局**。理由：力导向的默认初值来自随机数，同一张图两次打开形状不同——这正是 STATE 决策 11 否掉的东西（原文：「每次打开位置必须相同、不用 `Math.random`」，2026-10-29 已改为「固定起点松弛一次 + 存整章重心 `placeCloud`」）。孩子第二天回来找不到昨天那个点，图就废了。注意：**允许画得复杂，禁止位置随机**，这两件事别混。
2. **每次打开位置会变**（与 1 同源，单列因为它是用户能直接感知的后果）。理由：同上；且 G1 已把它写成可执行判据。
3. **全景当首页**。理由：竞品 `t01` 首屏就是 940 节点图【图上看过】，它解决的是「老师找一条路径」；我们的首屏要解决「今天做哪一节」，`#/today` 才是入口（`boot.js:8-11` 四个 tab：今日/目录/图谱/档案）。我们 673 个知识点、394 条先修边，一张全景既看不清也用不上。
4. **深色霓虹科技风**。理由：我看到的 15 张帧**全部是浅色**（白卡 + 浅灰蓝底 + 彩色小计数），竞品自己没做深色【图上看过】；我们的定案是 `--paper #f2f7fd` + `--green #0a7d5a`（app.css:27/32）。更硬的理由：孩子长时间读题，KaTeX 的分数线、根号钩子在深底上需要重新调对比，而根号在 15px 正文里已经量到 16.19px 高、要做 `scaleY(.88)` 压缩（app.css:738-745），深底会把这类细节问题放大。
5. **大量动效**。理由：我们的时长档只有 `--t-fast:120ms / --t-slow:240ms`（app.css:65），且这张图每次打开要做一次松弛计算；动效叠上去，孩子点一下要等两秒才看清。竞品在 15 张静帧里**没有任何一条能证明它用了动效**【图上看过：静帧无法证明】，所以「抄动效」连证据都没有。
6. **（低优先，不是禁止）教材原页阅读器**。竞品最得意的一屏（`t07`，我未看），但 STATE §6 已记「用户判定次要，不做」，analysis :843 也把它列进「不建议做」。理由：它是**防幻觉的仲裁器**，价值在「条目可疑时能翻回原页」；我们当前 673 个知识点全 `ai_draft`、没有教研复核环节，仲裁器做出来也没有触发场景。等真的出现「这条内容不对，翻书看」的争议时再补。
