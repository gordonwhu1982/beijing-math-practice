## 0. 结论速览

1. **家长要的不是"数据完备"，是"行为发生"**：打开 → 做题 → 立刻知道对错 → 错了能看懂 → 家长手里留下记录。当前仓交付的是前两层的**数据**，没有第三层之后任何一层。
2. **「孩子还不能用」的根因只有一个**：仓库里 0 个可运行的界面、0 行判题代码。15 次提交全部落在 `content/`、`docs/`、`tools/*.py`（校验脚本），`package.json / index.html / src / app / build.py / runtime/` 实测全部不存在。
3. **当前两周计划（P1–P4 + M4a）做完，孩子仍然不能用**：P1/P3/P4 补的字段（`uid/version/difficulty/validation`、知识点 `definition/conditions/objectives`、`skill/misconception`）都是"界面存在之后才有展示位"的字段；缺的是界面本身。
4. **一句话结论（§5）**：这两周只做「把题库变成孩子能双击打开、做完立刻有对错、且留得下一条记录的单个 HTML 文件」，其余全部延后。

## 1. 需求重述：家长真实目标 vs 我们已做的

### 1.1 家长的验收口径在文件里写得很清楚（不是我推测）

- `docs/plan/2026-10-26-data-architecture-v3.md:36`：「家长要「两周内能用」｜分层必须允许**半成品运行**：缺 answer_spec 就退 manual，缺 rubric 就不显示分步分」
  → 家长授权的是"半成品也能跑"，反过来说：**能跑 > 齐全**。
- 前提约束：「两周内孩子能真的每天用上」。可拆成 5 个可观测行为：
  ① 孩子能自己打开（不需家长开 IDE / 跑 python）；
  ② 每天有题可做（按节选题，20 分钟内一屏）；
  ③ 提交后立刻得到 correct/wrong/manual；
  ④ 错了能读到"这一步该写什么"（解析或 rubric 分步）；
  ⑤ 家长在自己仓库里能看见今天做了几道。

## 2. 两周可用版最小切片（5 项，每项一条可测验收）

判定标准：每一项要么让"孩子今天比昨天多做一道题"，要么让"家长第一次看见数据"。做不到这两件事的一律不进切片。

### S1（新）单文件练习页：`tools/build_page.py` → `build/web/ch12.html`
- 读 `content/questions/801/ch12.jsonl` + `content/rubric/801/ch12.jsonl` + `assets/vendor/katex/`，内联数据与渲染，**页面内零 fetch**（保证 `file://` 双击可用，无服务器、无 `http.server`）。
- 能力：12 个节标签切换（12.1–12.12 + 章末综合）；题面 KaTeX 渲染；题干/答案/解析三区折叠。
- **验收**：`python tools/build_page.py && ls -l build/web/ch12.html` → 单文件 ≤ 3.5 MB；`grep -c "fetch(" build/web/ch12.html` 输出 `0`；双击打开后 987 道含 `$` 题干渲染，浏览器 console error 数 = 0。

### S2（新）判题器 L0–L2：`runtime/judge.js`
- L0 归一（NFKC／全半角／`\lt{}`→`<`／去空格／中文数词最小集）+ L1 Fraction 精确比较 + **L2 多值默认无序**（按 `或 / 、 / ；` 切分后集合比较，`unordered:false` 才按序）+ 铁律「宁可 manual，不可假判 correct」。
- 输入不用等 P1：`answer` 字段 + 一条规则（`form ∈ {fill,choice}` 且 `answer` 含分隔符 → 默认 unordered）。
- **验收**：`node tools/judge_selftest.js` → 用例 ≥ 60 条全过；对 **120 道多答案题**构造 20 条断言，`wrong` = 0（这是旧引擎 98/120 判错的回归位）；`12.1_bas_02` 输入 `4<x<10` / `x>4且x<10` / `(4,10)` 三种写法均 correct。

### S3（必做，与 S2 同级）自评兜底：机器判不了的 825 题要有出口
- 题形实测：`fill 265 / choice 17 / calculation 21` = **303 题（26.9%）可自动判**；`solution 461 / proof 292 / construction 72` = **825 题（73.1%）必须自评**。
- 做法：这三种 form 不出输入框，出「展开标准答案 + 我做对了/半对/不会」三键；有 rubric 的 546 题按 `ordinal` 逐条折叠（3179 点已就绪）。
- **验收**：`12.5 全等判定` 一节 86 题中，自动判 5 道、自评 81 道，页面**无一个"无法判分"空白态**；三键点击后记录里 `verdict ∈ {self_correct, self_half, self_none}`。

### S4（必做）题目池过滤：把黑箱题挡在池外
- `figure.need=required` 且 `figure_ids=[]` 的题 + `answer_status=missing` 的题不进池，落 `build/report/no_figure.csv`。
- **验收**：`python tools/build_page.py --audit` 打印 `pool=629`（实测：不需必配图 662 − 缺答案交集 33 = 629）；分节打印后 `12.5=11`、`12.4=37` 与本文附录一致；池中「如图」题数 = 0。

### S5（必做，可放第二周）作答记录 + 一键导出（M4a 最小形态）
- 每次提交写 localStorage：`{attempt_id, qid, at, verdict, input, latency_ms, section}`；页面一个「导出作答」按钮产出 `.jsonl`；家长端 `python tools/attempt_import.py` 幂等写入 `private/records/<child>/evidence.jsonl`（按 `attempt_id` 去重），`python tools/mastery_view.py` 输出每节 `{state, evidence_count}`（入口按架构 v3 §14 第 2 条：只有这一个函数）。
- **验收**：孩子端连做 5 题 → 导出 5 行、`attempt_id` 唯一；同一文件导入两次后 `wc -l private/records/*/evidence.jsonl` 仍为 5；`mastery_view.py` 对 12.1 输出 `evidence_count>=3`。

### 3.1 最该砍的 2 项（附理由）

**砍① P2：三源边合并（1493 → 单文件 + uid + review 回填）**
- 理由 1（无消费者）：先修边的唯一产品出口是「补学出口（S6 屏）」，而 S6 依赖 `resource`（例题/讲解）——实测 `resource=0` 行，全仓「例题」只在 4 个文档里作为**规划**出现（`content/registry/schema.json:428`、架构 v3 `:93/:115`、`system-design-v2.md:160/164`），数据里 0 条。没有例题，"前置点回补"就是把人送到一个空白页。
- 理由 2（验收自证）：它的验收锚点是「1493 → 单文件；uid 100%；环 0；review 100%」，全是**数据自身的一致性**，没有一个指标能在界面上被孩子或家长观察到。
- 理由 3（成本/风险）：1493 条边 + review 回填 + `check_edge_evidence.py`，2–3 天，且任何一次合并失误都会污染全册框架（当前 394 条先修边是全仓唯一"已核"资产之一，见 `README.md:60`）。

**砍② P4 的 misconception + resource 首批（24 条错因 + 例题）**
- 理由 1：错因登记（S5 屏"概念不清/计算失误/审题/不会下手"）与「补学出口」都需要界面才有落点，而两周切片里没有 S5/S6 屏。
- 理由 2：24 条 misconception 是纯人工写作，占 2–3 天，两周内唯一效果是 `report.txt` 里 `misconception=0` 变成 `24`——**家长看不出差别，孩子用不到**。
- 替代：把这两天挪给 S3 自评兜底与 D8 的 30 题人工抽检——后者直接决定孩子的信任度（见 R2）。

### 3.2 最该加的 2 项（附理由）

**加① 单文件练习页（S1）**
- 理由：`README.md:49-55` 的 7 条命令没有一条产出可打开的东西，`ls package.json index.html src app` 全空——这是「孩子还不能用」的**唯一根因**。且必须做成**单文件内联**：无服务器 → 只能 `file://` 双击，而 `file://` 下 `fetch()` 被 CORS 拦（若做成 "HTML + 外部 JSON"，孩子得到一片空白页，家长会判定代码坏了）。
- 反面校验：P1–P4 全部做完，仍然是 0 个可打开界面。

**加② 判题器 + 自评兜底（S2 + S3 一起）**
- 理由 1（数量）：可自动判只有 **303 题（26.9%）**；若只做自动判，73.1% 的题提交后无反应。
- 理由 2（集中度）：越难越判不了。`12.5 全等三角形的判定` 86 题里可自动判**仅 5 道**（池内 11 道），`12.8 尺规作图` 85 题里**仅 4 道**。而 12.5 是全章的核心难点。
- 理由 3（信任）：自评是把"判对错"的责任交给孩子，所以 D8 的 30 题人工抽检必须和 S3 同期落地，否则一次错答案会永久毁掉"展开标准答案"这个交互（见 R2）。

> **这两周只做一件事：把题目池（629 道：1128 − 466 道无图 − 33 道无答案交集）变成一个孩子双击就能打开、做完立刻有对错或进入自评、每次作答都留得下一条记录的单个 HTML 文件**；P1–P4 中除 `answer_spec.unordered` 外全部延后。
